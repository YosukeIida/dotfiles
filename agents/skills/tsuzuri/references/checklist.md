# 確認項目

全体レビューの最後に、`checklist` で項目を一覧し、項目ごとに本文を確認して `confirm` で記録します。
記録には、確認した文の ID と、何を確認したかを書きます。
確認のあとで本文が変わると、その項目は「確認後に変更」になり、もう一度確認が必要です。
テンプレートを使う文章では、テンプレートの「## 確認項目」の節の項目が、この一覧の後ろに加わります。

項目は「- 名前: 確認すること」の形で記述します。
末尾の（条件: 語）は、要件定義書の「9. 文章の形」にその語がある文章だけに出す印です（語の書き方が揺れると項目が出なくなるため、どの文章にも要る項目には付けません）。
末尾の（判定: 名前）は、書き手の確認の代わりに tsuzuri が機械で判定する印です。
末尾の（候補: 名前）は、`load` の同じ名前の節に出る文を全部読んで確認する印で、`confirm` はその文の ID を全部含めないと記録しません。

## 確認項目

- 文体: 要件定義書の「9. 文章の形」で決めた文体（口語か文語か）にそろっている。文語なら、可能動詞の短い形（見張れる）は「〜することができる」、日常的な和語（書く・頼む・分かる）は定着した漢語にしている。読み手への問いかけの文（〜ませんか？）は、文語の文章でも口語のままでよい。要件定義書に文体の記述が無ければ、まず文体を決めて記述する（候補: 可能動詞の短い形）
- 用語: 一度定義した用語を、あとの文で別の言い方に変えていない。英語の用語を直訳した語は、定着した呼び名にするか、初出に英語を添えている
- 接続: load の「接続の確認」に出た文を全部読み、接続詞と接続助詞が前後の文の関係（理由・逆接・添加）に合っている（候補: 接続の確認）
- 所感: 調べた結果や注意を並べたままで終わる段落が無い。書き手の結論か、読み手が次にすることを書いている
